# Synthetic Engineering Test Assets

Original, synthetic engineering documents for testing the `/extract` pipeline, each with a
matching `*.golden.json` fixture in your exact schema (parts / dimensions / risks / tasks).
These are generated by me, so you own them and the ground truth is exact — better for a
regression harness than scraped drawings. PDFs are the primary `/extract` input; PNGs (150
dpi) give you the "technical image" modality.

For the adversarial Tier-0 test, just feed it any non-engineering photo (a cat, a
landscape). Expected output: empty arrays / low confidence. If it invents parts, your
guided_json + prompt discipline is wrong.

## How to use the golden fixtures

`confidence` in the golden files is set to 1.0 to mean "this is definitely present" — it is
NOT a target for the model's confidence. Assert against the golden like this:

- parts/dimensions: every golden entry's `name`/`label` appears in the model output, units
  match, enum/range valid. Don't require exact string match on free-text fields.
- risks: the high-severity golden risks are present (e.g. asset_02's thin wall, asset_04's
  three defects). Extra lower-severity risks are fine.
- confidence: assert it's a float in [0,1], not that it equals the golden value.
- asset_06: assert all 6 BOM parts appear with correct quantities — this catches page-budget
  truncation directly.

## Notes

- These are schematic but valid engineering drawings (title blocks, dimension lines,
  ASME Y14.5 references). They read as engineering documents to a VLM; they are not
  manufacturing-grade and shouldn't be used as real drawings.
- To make a degraded Tier-3 input, rotate or add noise to any PNG (e.g.
  `convert asset_01_machined_bracket-1.png -rotate 7 -blur 0x1 noisy.png`).
